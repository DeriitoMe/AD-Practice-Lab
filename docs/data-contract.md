# AD Practice Lab · 数据与埋点口径

## 三类材料，分别保存

| 材料 | 来源 | 保存与读取 |
|---|---|---|
| 课程算例和小测 | `static/curriculum.json`，独立手算例 | 浏览器读取；答对进度留在 localStorage |
| 交互模拟结果 | `simulation.py` 固定教学公式 | `/api/simulate` 返回，最近两次留在浏览器；不写入 `ad_daily` 或 `datasets` |
| 固定案例与导入数据 | 程序生成的 4×14 天 CSV，或用户导入的模拟 CSV | SQLite `ad_daily` / `datasets`，`source_kind=simulation` |

`product_events` 单独保存本地练习请求及自动化自测，`source_kind=local_practice`。它不是广告受众行为，也不代表真实客户使用量。模拟器会记录操作事件，但不把结果转成案例数据。

## 交互模拟：输入

接口为 `POST /api/simulate`，JSON 形状为 `{"config":{...},"session_id":"标签页会话"}`。`config` 必须是对象；支持字段缺省时使用下表默认值，未知字段或不支持的选项会报错。

| 字段 | 支持值 | 默认值 |
|---|---|---|
| budget | 100–50000 元的有限金额，最多两位小数；不接受布尔值 | 1000 |
| audience | broad 广泛人群 / focused 通勤人群 | broad |
| creative | feature 功能介绍 / benefit 使用收益 / story 场景故事 | benefit |
| landing | basic 基础商品页 / clear 清晰商品页 | clear |
| bid | balanced 均衡 / reach 覆盖优先 | balanced |

币种为 CNY，目标为购买，商品价格 199 元/单、商品及履约变动成本 99 元/单。预算是这一次完整虚拟投放的总预算，不是某天实际广告账户额度；选项不对应真实平台竞价参数。

## 固定教学模型

模型版本为 `commuter-bag-v1`。基准 CPM=24 元、CTR=0.012、到达后购买率=0.05。各配置采用以下公开假设：

| 配置 | CPM 倍数 | CTR 倍数 | 到达率 | 到达后购买率倍数 |
|---|---:|---:|---:|---:|
| broad | 1 | 1 | — | 1 |
| focused | 1.3 | 1.1 | — | 1.25 |
| feature | — | 0.85 | — | 1.15 |
| benefit | — | 1.1 | — | 1 |
| story | — | 1.6 | — | 0.6 |
| basic | — | — | 0.72 | 0.65 |
| clear | — | — | 0.92 | 1.15 |
| balanced | 1 | 1 | — | 1 |
| reach | 0.8 | 0.9 | — | 0.8 |

CPM=24×人群倍数×分配策略倍数；CTR=0.012×人群倍数×素材倍数×分配策略倍数；到达率由商品页配置直接决定；到达后购买率=0.05×人群×素材×商品页×分配策略的购买率倍数。

按以下顺序计算，使用 Decimal 处理教学预算与中间参数：

1. 曝光=`floor(预算×1000/模型CPM)`。
2. 点击=`floor(曝光×模型CTR)`。
3. 有效到达=`floor(点击×模型到达率)`。
4. 购买=`floor(有效到达×模型到达后购买率)`。
5. 花费=`曝光×模型CPM/1000`，向下保留两位小数，不超过预算；收入=购买×199，变动成本=购买×99。
6. 使用下文共同指标公式重新计算展示比率。因此取整后的 CTR/CVR 可能与理论模型参数略有不同。

模拟器无随机数、真实流量或网络调用；函数不写数据库。结果是完整观察后的整段汇总，不含日期、归因延迟、退款、竞价波动、预算饱和、重复用户或增量因果分析。参数不是行业基准或效果预测。

返回字段为 `config`、`totals`、`metrics`、`funnel`、`label`、`model`、`model_assumptions`、`insights`。`funnel.rate_from_previous` 为当前计数/上一层计数，首层或上一层为零时为 null；`metrics.cvr` 则始终使用购买/点击，不能与模型的到达后购买率混用。

## 模拟比较与浏览器进度

页面只保留最近两次成功返回的模拟，比较配置变化、曝光、购买、花费、CPA、ROAS 和贡献利润。差值为本次减上次；任一 CPA 不可计算时显示“无法比较”。多项配置变化无法单独解释某项影响，相同配置产生相同输出。该比较是模型响应，不是真实 A/B 实验。

课程通过状态、最近两次结果、模拟笔记和创意实验笔记保存在当前浏览器。localStorage 按协议、主机、端口组成的 origin 隔离；换端口、换主机名或清理网站数据会使用不同或清空的记录。固定端口和同一浏览器可复用，但没有账号同步。

`my_ad_practice.md` 包含客户端生成的导出时间、课后通过数量、最近两次配置与指标、本人填写的观察和证据范围；`my_experiment.md` 包含诊断假设与实验计划。下载由浏览器生成，不新增服务端导出事件，也不证明文件已保存或内容已掌握。

## 案例投放表

每行代表“一个数据集中的某天、某计划、某素材”。唯一键为 `dataset_id＋date＋campaign_id＋creative_id`。同一整份文件重传命中内容哈希，复用原数据集；不同内容作为独立版本保存，统计时必须选择 `dataset_id`。

| 字段 | 类型和含义 |
|---|---|
| date | YYYY-MM-DD；广告点击发生日，曝光与花费使用同一日粒度 |
| campaign_id / campaign_name | 计划编号与名称；同一文件内编号与名称一致 |
| creative_id | 素材编号 |
| impressions / clicks | 曝光与点击次数 |
| landing_views | 点击后的有效到达；教学假设每次点击最多一次有效到达 |
| purchases | 归因购买；教学假设每次有效到达最多一笔购买，订单不跨计划重复 |
| spend | 广告花费，人民币元，最多两位小数 |
| revenue | 这些归因购买对应的收入 |
| variable_cost | 对应商品与履约变动成本；固定案例按 99 元/单生成 |
| currency | 固定 CNY |
| attribution | 固定 7d_click |
| source_kind | 固定 simulation |

真实平台可能有多次购买、浏览归因、跨设备或小数归因，这些教学漏斗约束不能直接套用。

固定截至日为 `2026-10-10`，按北京时间当日 00:00 理解。为保证全天 7 天点击归因窗已结束，保留 `date < 截至日−7天` 的日期。固定案例为 2026-09-19 至 2026-10-02，共 56 行，在默认截至日均成熟。

诊断选择最近连续 14 个成熟日期，拆为前 7 天/后 7 天；每个计划须覆盖完整窗口。真实平台还可能存在报告延迟和更正，成熟过滤不能替代对回传的持续检查。模拟器没有日期，不受该过滤影响。

## 共同指标公式

| 指标 | 公式 |
|---|---|
| CTR | 总点击/总曝光 |
| 点击购买 CVR | 购买/点击 |
| 到达率 | 有效到达/点击 |
| 平均 CPC | 广告费/点击 |
| 实际 CPM | 广告费/曝光×1000 |
| 购买 CPA | 广告费/购买 |
| ROAS | 归因收入/广告费 |
| 贡献利润 | 收入−变动成本−广告费 |
| 简化教学 ROI | 贡献利润/(变动成本＋广告费) |

缺分母输出 null，界面显示“—”，不解释为零成本。汇总先合计分子分母，不直接平均各行百分比。ROI 未纳入固定成本、税费和退款调整；ROAS 的归因收入也不等于增量收入。

例如独立手算例：广告费1000元、收入4000元、变动成本2000元，贡献利润1000元，ROAS=4倍，ROI≈33.33%。它不等于按商品199/99元参数运行的模拟器或固定案例结果。

SQL 使用 SQLite REAL 保存教学金额，输入最多两位小数，展示四舍五入；不用于账务结算。

## 案例诊断规则

完整窗口内，CTR 相对下降超过 30%、到达率相对下降超过 25%、CPM 相对上升超过 30%时提示检查。任一期曝光不足1000或点击不足30时标记样本不足。零购买与负贡献利润有单独提示。

这些是可解释的训练规则，不是平台官方阈值。触发规则不证明素材疲劳、页面故障、竞争加剧、因果或统计显著性。模拟器的两次配置比较与案例的前后两期诊断也不是同一操作。

## 本地练习事件

| 事件 | 触发 | 解释范围 |
|---|---|---|
| dashboard_viewed | 页面初始化、案例指标载入后由浏览器请求 | 工作台初始化记录，不证明学习者主动看过所有模块 |
| lesson_answered | 每次点击课后选项后由浏览器请求 | properties 含 lesson_id、correct；服务器校验字段，不重新判题，标记为 self_reported_practice_answer |
| simulation_started / simulation_finished | 接收模拟请求后开始 / 计算成功或失败结束 | success 只表示固定公式计算完成；失败含 error_type，不代表真实投放结果 |
| import_started / import_finished | CSV 导入开始 / 校验及写入结束 | 重复文件复用数据集也算操作成功；错误文件不写入 |
| diagnosis_started / diagnosis_finished | 诊断请求开始 / 返回结果或异常 | success 表示程序完成；样本不足可正常返回，不代表广告问题已解决 |
| creative_started / creative_finished | 模板草稿请求开始 / 返回或失败 | 不代表素材通过审核或实际有效 |
| sql_started / sql_finished | 查询开始 / 返回结果或报错 | 写入 SQL 被拒绝记为失败 |
| report_exported | 服务端生成可下载的案例 JSON 响应 | 不证明用户已保存或阅读；不涵盖浏览器生成的学习 Markdown |

事件包括 `event_id`、`session_id`、`run_id`、`occurred_at`、`received_at`、`dataset_id`、`outcome`、`duration_ms`、`properties_json`、`source_kind`。时间以 UTC 保存，当前均由本地服务接收时创建，两时间相同；不代表浏览器实际答题时间。

`event_id` 唯一约束去重，开始/结束通过 `run_id` 关联。`session_id` 是标签页会话，不是独立学习者身份；模拟与小测通常不关联案例 `dataset_id`。课程 correct 是客户端自报值，不能用于可靠的能力认证或独立掌握率统计。

开始事件后进程中断可能没有结束事件，应单列未结束。HTTP 自动重试目前会成为新操作；未实现跨请求业务幂等。课程事件请求失败不会回滚浏览器已保存的通过状态，因此浏览器进度与事件库不能视为同一份权威记录。

## 如何用记录提出下一轮需求

观察一次真实练习的输入、卡点与本人解释，例如 SQL 字段错误、零购买误读或多变量变更。再提出字段提示、错误分类或更清楚的比较说明，并用相同任务复核。自测事件、服务成功和可重答小测不足以证明真实用户价值或业务增长。
