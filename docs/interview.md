# AD Practice Lab · 作品集与面试复盘

项目名称可用：**AD Practice Lab · 广告投放练习室｜Python / SQLite 教学产品**。

本页按当前已实现功能整理作品集表达。个人职责可围绕需求设计、AI 协作开发、功能测试与迭代说明，并保留自己实际参与的操作与判断。模拟数据、本地自测、真实用户反馈和真实投放成果分别陈述。

## 作品集三点功能描述

- **学习路径与产品设计：**面向广告初学者组织六节概念短课、小测反馈、虚拟投放与复盘路径，解释广告角色、漏斗、成本指标和归因；提供官方来源、浏览器进度与 Markdown 学习记录。
- **模拟与数据分析：**基于 Python 标准库和 SQLite 提供五项配置的固定公式模拟、漏斗与成本输出、最近两次方案比较；独立保留 4×14 天案例的 CSV 校验、版本隔离、成熟窗口和规则诊断，并用只读 SQL 复核。
- **方法封装与验证：**将案例排查整理为知识卡、Skill 和五个 MCP 只读工具，记录本地操作开始/结束及自报答题事件；提供模板创意、实验笔记、测试与本地启动器，明确计算、用户记录和真实效果的证据边界。

以上适合作品集功能介绍。用于个人简历时，把“组织”“实现”“验证”等动词限制在你确实参与且能够解释的部分，例如“通过 AI 协作完成……功能设计、开发与验证”。不要增加真实客户、实际广告预算、业务收入或效率提升数据。

## 决策问答：解释方法，补充自己的操作

### 为什么把六课、模拟和复盘串起来？

产品希望学习者先知道角色、目标与分母，再配置一个方案，观察结果并写判断。六课提供基础，模拟让配置可操作，复盘要求用自己的话解释变化。这个设计是否提高学习效果，需要真实任务测试；当前只能展示路径与功能实现。

### 为什么使用固定公式模拟？

固定参数让一次配置的结果可复现，也能公开中间公式和取整方式。它适合练预算、漏斗和成本之间的关系。参数来自虚构情境，未模拟竞争、流量波动、预算饱和或增量因果，不能作为真实投放预测。

### 为什么只比较最近两次，而且提示只改一项？

两次结果让学习者集中解释一次改变。若同时改素材、人群与页面，无法把差异单独归给某项；页面会列出变更数。即使只改一项，比较也只体现模型设定，不是随机分流的真实 A/B 实验。

### 模拟器结果为什么不能直接进入诊断案例？

模拟器是一次完整虚拟投放汇总，没有日粒度和归因延迟。案例诊断需要按日期、计划、素材存储的明细及连续14个成熟日期。把两者混在一起会破坏粒度、日期和归因口径，所以模拟结果留在浏览器，案例保存在 SQLite。

### CTR、CVR、CPA 怎么联系？

CTR=点击/曝光；本项目 CVR=购买/点击；CPA=花费/购买。同一口径且分母非零时，CPA=CPC/CVR=CPM/(1000×CTR×CVR)，百分比代入小数。该等式拆解成本变化，不自动确认原因，也不代表平台一定按购买收费。

### ROAS 为4倍，是否说明赚了4倍？

只说明每1元广告费对应4元归因收入。独立手算例中，花费1000元、收入4000元、变动成本2000元，贡献利润1000元，简化 ROI=1000/(2000+1000)≈33.33%。还要考虑实际成本和退款，并区分归因收入与增量收入。

### B计划CTR下降，为何不直接写素材疲劳？

CTR变化是证据，素材吸引力、受众和版位构成变化是不同解释。先核对数据与变更，再补素材版本、频次、分人群分版位资料，设计可比验证。30%是教学规则阈值，没有证明行业通用、统计显著或因果。

### 为什么剔除归因观察窗未满的日期？

案例固定为7天点击归因，近期点击的购买可能尚未全部记录。按截至日00:00保守保留 `date < 截至日−7天`，再比较连续成熟日期。真实平台还需检查回传延迟、更正、归因模型和跨平台去重。

### 小测通过或事件 success 能证明掌握吗？

不能。小测可以重答，correct由浏览器自报；服务端只校验字段和保存记录。success只表示计算或操作完成。掌握应另外看本人能否手算、解释分母、提出替代假设、修改查询并复核。标签页session_id也不是独立用户数。

### 为什么使用浏览器本地进度？

本地练习无需账号，刷新同 origin 能继续。代价是浏览器、主机和端口变化会使用另一份存储，清理数据会清除记录。固定端口便于继续学习，Markdown下载用于保留本人判断；当前没有云端同步。

### Skill、MCP、Agent完成到哪一步？

Skill组织案例排查方法，MCP提供五个只读数据工具。协议和基础调用已做本地检查。真实客户端连接、自主选工具和答案组织仍需要实际联调；固定规则诊断流程不能直接当作已验证的完整 Agent。

### 创意和模型解读怎样评价？

模板创意先核对商品事实、承诺、可读性与素材使用，再设计主指标和可比条件。可选模型解释要核对数字、引用、遗漏和失败情况，不能仅看文字顺畅。当前没有真实创意投放或模型质量评测结果。

## 可复现的边界与失败场景

这些是产品可以复现的教学场景，不自动成为你亲历的开发故事。亲手操作后，保留输入、预期、实际结果和复核。

| 场景 | 处理或判断 | 面试可以解释的取舍 |
|---|---|---|
| 预算超范围、非法金额或未知模拟选项 | 服务端拒绝并返回可读错误 | 界面控件不能代替后端校验 |
| 向下取整后购买为0 | CPA返回null，显示不可计算；收入与变动成本为0 | 不把无法计算误写成0元成本 |
| 多项配置同时变更 | 展示变化项，提示难以单独解释 | 结果变化不直接等于单变量效果 |
| 重传同一CSV | 内容哈希命中原数据集，不重复累加 | 重复导入和新版本分别处理 |
| 日期未成熟或缺连续14天 | 排除未成熟日期，数据不足时停止比较 | 宁可保留未知，也不把延迟回传当成效果下降 |
| SQL字段不存在、写入或多语句 | 返回错误，记录操作失败；只读查询受限 | 让失败可解释，保持案例数据稳定 |
| 浏览器存储不可用或换端口 | 当前会话可练习、下载；无法保证跨次恢复 | 存储范围在说明中明确，保留可携带记录 |
| 开始事件后进程中断 | 可能缺结束事件，统计时单列未结束 | 未结束不能静默当成功、失败或删除分母 |

真正的个人迭代故事按“发现问题—优先理由—修改点—预期—复核—局限”讲，附上差异和结果。讲述时补充自己实际参与的过程与验证记录。

## 三分钟演示顺序

1. 介绍初学者场景，打开一课解释目标和分母，完成小测。
2. 运行默认虚拟计划，展开模型与公式，再只改一个选项运行并比较。
3. 写一句本人判断，导出Markdown，解释模拟结果的适用范围。
4. 展示独立4×14天案例，说明一条异常的证据、两个解释和下一步。
5. 修改一个SQL条件核对结果，最后展示本人实际改动与复测记录。

如果尚未亲手完成其中某步，演示时说明是提供的功能，不将其当作已掌握的个人能力。
