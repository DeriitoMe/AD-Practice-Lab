## 3. 广告行业里的几类角色

用虚构商品“轻行通勤双肩包”举例：品牌商希望销售背包，它是**广告主**。广告主可以自己操作，也可委托**代理商**做开户、素材、投放和服务。**广告平台**提供账户、计划、竞价、定向、审核、报表等能力。**媒体**提供用户看到广告的位置，如搜索结果、短视频信息流、资讯页面、应用广告位。平台与媒体可能属于同一公司，但角色并不相同。**用户**看到广告、点击、进入页面并可能购买。广告主还需要落地页、订单系统、客服和库存履约配合。

代理团队的Agent一词在英文也可能指代理机构；本岗位AI语境下的Agent通常是能够调用工具执行任务的智能体，需要结合上下文判断。

进一步会遇到：DSP是需求方购买广告的技术平台，SSP帮助媒体管理与出售广告库存，广告交易平台连接供需。本岗位入门先掌握投放后台的任务与数据流；无需把所有平台都想成同一种交易结构。

## 4. 一次广告投放怎么发生

1. **确定业务目标。**是让更多人记住品牌、获取咨询线索，还是获得购买？目标决定转化事件与评价指标。
2. **准备承接与测量。**确认落地页可打开、商品价格与素材一致、购买事件可回传、订单可去重、归因口径一致。
3. **设预算和出价策略。**预算决定计划可花多少钱；出价表达争取流量的意愿或优化目标。实际花费由投放情况决定，预算不等于实际消耗。
4. **选定向、版位与素材。**确定希望触达的人群或信号，在相应位置展示文字、图片、视频等创意。
5. **创建与审核。**准备账户与商品资质、提交计划和素材；审核、余额、计划状态都会影响能否投放。
6. **进入分配/竞价与学习。**用户产生广告机会时，系统根据相关信号进行分配或竞价；平台细节各异。单纯提高出价并不保证商业效果。
7. **监测交付与数据。**先看是否正常消耗、回传是否完整，再看CTR、CVR、CPA、ROAS等。
8. **诊断、实验、复盘。**结合完整观察窗口与变更记录定位问题；一次主要改变一个变量；记录结果与局限。

Google官方将购买、注册、电话等有价值行为作为转化测量的典型对象。[转化衡量简介](https://support.google.com/google-ads/answer/1722022?hl=zh-Hans)

## 5. 广告类型：目标与展示形式是两个维度

| 维度 | 类型 | 白话例子 | 常见观察重点 |
|---|---|---|---|
| 业务目标 | 品牌广告 | 新背包品牌希望更多目标人群认识它 | 覆盖、频次、可见曝光、品牌认知研究等 |
| 业务目标 | 效果广告 | 希望获得购买、咨询、下载等可测行为 | 转化数、有效线索率、CPA、收入与利润 |
| 展示形式/场景 | 搜索广告 | 用户主动搜“通勤电脑双肩包”时看到相关广告 | 搜索意图、关键词、相关性、购买转化 |
| 展示形式/场景 | 信息流广告 | 用户刷内容时看到通勤收纳视频广告 | 首屏吸引、素材与人群匹配、点击后承接 |
| 展示形式/场景 | 展示/视频广告 | 网站广告位、视频前后或视频内容流展示 | 触达、注意力、频次与后续转化 |

品牌广告也可以放在信息流里，效果广告也可以使用视频。不能把“品牌/效果”和“搜索/信息流”当成四种互斥分类。[巨量引擎官网场景介绍](https://www.oceanengine.com/)

## 6. 基础概念

| 术语 | 含义与容易混淆的地方 |
|---|---|
| 曝光/展示 | 广告被展示的次数；同一个人可以贡献多次曝光，曝光不等于独立人数，也不保证充分注意到广告 |
| 点击 | 用户点击广告的次数；点击不必然等于成功打开落地页 |
| 转化 | 预先定义的有价值行为。本项目固定为购买；留资CPA与购买CPA不能直接比较 |
| 定向 | 用地域、兴趣、上下文等条件或信号寻找适合的受众；智能扩量等机制需看平台规则 |
| 出价 | 手动价格或目标CPA/ROAS等竞价策略参数；目标不保证每一笔结果都达到 |
| 预算 | 计划花费安排或限制；具体日预算、超投与计费规则因平台而异 |
| 素材/创意 | 广告的文案、图片、视频及组合表达；同一商品可以测试不同表达角度 |
| 落地页 | 点击后承接用户的页面、商品详情或应用内页面；加载、信息一致性、表单与支付都可能影响结果 |
| 归因 | 按规则把转化功劳分配给广告触点。窗口是允许计入转化的时间范围，模型是分配功劳的方法 |
| 回传 | 把购买、线索等事件及价值交给测量系统；事件名、时间、ID、金额与去重需要统一 |
| 冷启动/学习期 | 系统对新计划或变化后的计划积累信号的阶段；时长和退出条件依平台与场景而定 |
| 频次 | 同一人在特定窗口平均看到广告的次数；需要覆盖人数等数据，不能用曝光总数直接代替 |

归因收入不等于广告带来的增量收入。同一订单可能被不同平台各自归因，跨平台汇总需要统一去重。平台归因模型还可能影响智能出价学习。[归因模型简介](https://support.google.com/google-ads/answer/6259715?hl=zh-Hans)

## 7. 指标计算：同一组数字看懂全部概念

独立教学算例：广告费1000元，曝光100000次，点击1000次，归因购买20次，归因收入4000元，商品/履约等变动成本2000元。统一窗口、币种与转化目标；这不是项目运行结果。

| 指标 | 公式与分母 | 算例 | 用于观察 |
|---|---|---|---|
| CTR 点击率 | 点击/曝光 | 1000/100000=1% | 广告展示后获得点击的比例 |
| CVR 点击购买转化率 | 购买/点击 | 20/1000=2% | 点击后的购买表现；其他平台可能使用互动或到达作为分母 |
| 平均CPC | 广告费/点击 | 1000/1000=1元 | 获得一次点击的平均费用 |
| 实际CPM | 广告费/曝光×1000 | 1000/100000×1000=10元 | 每千次曝光的平均费用 |
| 购买CPA | 广告费/购买 | 1000/20=50元 | 获得一次归因购买的平均广告费用 |
| ROAS | 归因收入/广告费 | 4000/1000=4倍=400% | 每1元广告费对应多少归因收入 |
| 贡献利润（本例） | 收入−商品变动成本−广告费 | 4000−2000−1000=1000元 | 本例成本范围内剩余的金额 |
| ROI（本例成本口径） | 贡献利润/(商品变动成本＋广告费) | 1000/3000=33.33% | 明确成本范围后的利润回报比例 |

CPC/CPM既可能用来描述计费/出价方式，也能作为事后计算的成本指标。**计算出CPA，不代表平台一定按转化收费**；目标CPA是优化目标，也不等于逐单成本保证。[平均CPC](https://support.google.com/google-ads/answer/14074?hl=zh-Hans)、[CPM定义](https://support.google.com/google-ads/answer/6310?hl=zh-Hans)

不同团队可能把“ROI”口语化地用于成交金额/广告费，面试和对接时先问清公式。该比例在本文统一称ROAS。本文ROI采用已明确的利润/成本口径；实际业务还要考虑退款、税费、固定成本等。[投资回报率简介](https://support.google.com/google-ads/answer/1722066?hl=zh-Hans)

有用的分解：在同一统计口径、分母非零时，CPA=CPC/CVR=CPM/(1000×CTR×CVR)。CTR和CVR代入小数，例如1%=0.01。这个等式帮助拆解“成本贵在哪里”，不自动证明原因。

汇总时用总量重算。例如A素材100次曝光10次点击，B素材10000次曝光100次点击，总CTR=110/10100≈1.09%，不能把10%和1%简单平均成5.5%。购买为0时CPA应显示不可计算；花费为0时ROAS同样不可计算。

## 8. 怎样从数据定位问题

| 现象 | 可以提出的假设 | 先补什么证据 | 可考虑的验证 |
|---|---|---|---|
| 没有消耗/曝光 | 审核、余额、开关、预算、定向或竞价限制 | 账户状态、诊断提示、预算/出价、计划变更 | 复现配置、排除硬性阻塞后再小范围测试 |
| CTR下降 | 素材吸引力变化、受众/版位构成变化 | 素材版本、频次、分人群分版位数据 | 固定主要条件测试创意变化 |
| 点击正常，到达下降 | 加载、跳转、统计漏报或流量质量变化 | 页面速度、错误日志、点击与到达埋点 | 复现页面流程、检查回传 |
| 到达正常，购买下降 | 商品价格/库存/承诺不一致、结算问题 | 订单、漏斗、页面变更、客服反馈 | 检查交易链路，再测试页面或商品表达 |
| CPM上涨 | 出价、人群、版位或竞争环境变化 | 变更记录、流量结构、同期数据 | 拆维度比较，避免同时改太多变量 |
| ROAS高但利润低 | 毛利低、成本/退款未纳入 | 商品成本、退款、履约和收入确认口径 | 重算利润与可承受CPA |

“CTR下降就是素材疲劳”只是一个待验证假设。自然波动、季节、预算、受众与观察窗口也可能影响结果。

## 10. Skill、MCP、Agent怎样配合

- **Skill：**工作方法与配套资源。例如先确认归因口径，再检查样本、计算指标、提出假设。项目内的SKILL.md写的是这个方法。[官方Skills概念](https://developers.openai.com/plugins/concepts/skills)
- **MCP：**让支持该协议的AI客户端发现并调用工具的接口协议。例如列出数据集、获取指标、查询知识卡。接口不自行判断业务问题。[MCP工具规范](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)
- **Agent：**围绕用户目标，选择工具、读取结果、继续判断并组织输出的执行者。可以读取Skill方法，再通过MCP调用本项目的数据能力。要评价任务完成情况与工具行为，不能只看回答流畅度。

本项目已实现固定步骤的诊断工作流、Skill文件和MCP stdio工具。网页默认使用规则诊断、关键词知识检索与模板草稿。可选模型接口用于解释现有证据；真实模型联调与AI客户端中的自主工具调用需另行实际验证，不能仅凭接口文件宣称完成完整智能体产品。

## 11. 智能工具推广与商业化怎么看

岗位提到“客户覆盖”，可以先定义一个采用漏斗：具备使用资格的客户→收到介绍→启用功能→首次成功完成任务→在约定窗口再次使用。每一步要明确客户去重、资格条件、观察窗和成功定义。推广材料的曝光量不能代替成功使用人数。

商业化初步研究可包括：客户是否反复遇到同一问题、现有人工成本、愿意为哪种结果付费、工具调用成本、支持成本与留存。按席位、用量或服务包收费只是候选假设，要经过真实访谈与试点。实习生可以产出方案和小范围验证记录，不能把设想写成实际收入。

## 12. 这次实训如何对应岗位

详见PRD、数据与事件说明、分阶段练习、面试材料。先亲手跑通一轮，再选一处改动完成第二轮：例如新增“零购买”诊断案例、改变观察截至日、增加错误类型分组、修改一条规则并解释取舍。你的复盘记录比项目名称更能证明你掌握了方法。
