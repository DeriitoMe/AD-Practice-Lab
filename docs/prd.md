# AD Practice Lab · 产品设计说明

版本：2.0。定位：面向广告初学者的本地教学工作台。用户困难和需求价值目前来自学习场景假设，尚无真实广告主访谈或可用性测试结论。

## 用户、问题与学习目标

主用户：第一次接触广告角色、指标和投放链路，希望用具体操作理解概念的学习者。次用户：需要核对数据、展示方法和复盘教学案例的产品实习候选人。

待验证问题：初学者可能会把预算等同实际花费、把点击当购买、混淆 ROAS 与 ROI、平均百分比、忽略归因窗口，或把异常当成已确认原因。只提供报表容易让学习者不知道下一步该做什么。

学习目标：走完“读概念—回答小测—配置计划—只改一项—看漏斗与成本—写判断—诊断案例—设计实验—SQL 核对”的过程。可交付证据是一份学习者自己填写的复盘和可复核的结果；答题通过、程序成功与独立掌握分别记录。

## 教育闭环与产品决策

| 决策 | 目的 | 已实现行为与适用边界 |
|---|---|---|
| 六个短课作为入口 | 先建立角色、目标、分母和成本概念 | 每课有短文、独立算例、术语、官方来源和三选一小测；可自由选课 |
| 固定公式可交互模拟 | 让选择与结果之间的关系可解释、可复现 | 五项配置，模型参数与取整规则可查看；相同配置返回相同结果 |
| 只保留最近两次模拟 | 让学习者集中比较一次改动 | 显示配置变化及指标差值；多项变更提示不能单独解释某项影响 |
| 请求学习者写一句判断 | 把运行结果转成自己的解释 | 有模拟结果且填写观察后才能导出学习 Markdown；文字不自动评分 |
| 案例诊断接在模拟之后 | 练习从真实格式的报表提出问题 | 独立的 4×14 天固定模拟案例；规则给证据、假设、核实动作和来源 |
| 模板创意连接实验设计 | 把表达想法变成可检验计划 | 三类草稿、诊断假设与实验笔记；保存下载不表示实验已执行 |
| SQL 作为进阶核对 | 练习分母、汇总、版本和操作记录 | 四个可修改网页示例、五份 SQL 文件，查询只读且限制行数 |
| 浏览器保存进度与笔记 | 无需账户即可继续练习 | 本地存储按 origin 隔离；固定端口可复用，不能跨浏览器同步 |

## 用户故事与验收

| 用户故事 | 验收条件 |
|---|---|
| 我想逐步理解广告概念并核对答案 | 六课内容可读；每题三个选项；答错给反馈；答对更新 0/6 进度并可进入下一课；刷新同 origin 后进度可恢复 |
| 我想设置一个自己的虚拟计划 | 预算 100–50000 元、最多两位小数；人群、素材、商品页和分配策略选项与模型一致；非法配置由服务端拒绝 |
| 我想知道数字从哪里来 | 展示漏斗、花费、购买、CPA、ROAS、贡献利润、ROI 和参数说明；逐层计数向下取整，花费不超过虚拟预算；零购买的 CPA 显示不可计算 |
| 我想只改变一个条件再比较 | 最近两次结果和变化项一致；相同配置结果一致；两项以上变更有说明；零分母指标不被当作零成本比较 |
| 我想保留自己实际完成的学习 | 填写判断后可下载含配置、结果和本人笔记的 Markdown；注明模拟数据、答题记录及验证范围；本地存储不可用时仍可下载 |
| 我想排查预设案例，而不是猜原因 | 诊断要求连续 14 个成熟日期，分前后两期；样本不足时停止或提示；每条提示包含证据、原因假设、核实动作与知识来源 |
| 我想导入模拟报表并自己核对 | 格式、金额、漏斗和归因错误不写入；重复文件不累加；不同版本隔离；总比例先汇总数量再计算 |
| 我想把创意做成实验计划 | 模板遵守商品事实；可填写变量、主指标、可比条件和局限；下载包含本人诊断假设与实验计划，不声明真实效果 |
| 我想用 SQL 复查过程 | SELECT、汇总、关联、窗口示例能修改；写入和多语句被拒绝；最多返回 200 行；失败可查看练习事件 |
| 我想把案例方法交给 AI 客户端 | Skill 和五个只读 MCP 工具可供接入；协议与基础调用做本地自测，客户端自主调用另行验证 |

## 输入、输出与数据流

1. **课程：**`static/curriculum.json` → 浏览器阅读与判题 → 浏览器进度；`lesson_answered` 仅记录客户端自报答题结果。
2. **交互模拟：**五项配置 → `/api/simulate` → `simulation.py` 固定参数与取整 → 指标、漏斗、假设说明 → 浏览器最近两次结果与 Markdown。模拟结果不写入案例明细表。
3. **案例分析：**模拟 CSV → 字段/唯一键/口径校验 → SQLite 数据集隔离 → SQL 聚合与成熟窗口 → 规则诊断 → 官方知识卡 → JSON 报告。
4. **操作记录：**模拟、导入、诊断、创意与 SQL 请求 → 开始/结束事件 → `product_events`。操作完成不能自动代表学习完成或业务问题解决。

课程、模型模拟和案例报表使用独立练习数字；归因窗口只作用于有日期的案例。具体字段见 [数据口径](data-contract.md)。

## 范围与优先级

P0：初学者能顺利完成一个闭环；数字、分母和取整正确；模拟与案例区分；错误有可理解提示；答题状态与笔记可恢复和导出。

P1：案例诊断、官方知识卡、只读 SQL、模板创意、Skill/MCP 方法封装及本地操作记录。当前实现已提供，实际验证范围以 [验收记录](verification.md) 为准。

P2：真实用户任务测试、真实模型联调与评测、客户端 Agent 自主编排、多平台口径、云端服务和多人权限。当前不把这些列为已完成能力。GitHub Actions 测试配置已提供，云端运行仍待执行。

虚拟商品为通勤双肩包，售价 199 元、变动成本 99 元/单；预算配置用于教学模型。固定案例另有 14 天虚拟预算 30000 元设定，用于复盘，不控制实际充值或花费。

## 学习与产品验证

先观察学习者能否正确完成四类任务：计算一次 CPA 与 ROI；解释一次单变量比较；为异常写两个原因假设；独立改一条 SQL 并核对。记录实际完成情况、误解、卡点、耗时和需要的提示。

已有小测和操作事件不能代替这些任务评测：小测可重答，`correct` 为客户端自报，运行成功只说明程序完成。本机自测记录也不能用于报告真实学习者规模、掌握率或留存。

比较两种教学路径时，使用难度相当的任务、约定评分标准并控制学习效应。少量试用先用于发现问题，不报告统计显著的效率或业务收益。

## 后续访谈与试用提纲

1. 请描述你最近一次学习广告指标或读报表的过程，哪里停住了？
2. 当时你如何确认“点击”“购买”和“收入”的分母与来源？
3. 请边操作边说出你对一次模拟配置的预期，再解释结果。
4. 比较两次方案时，你会先看哪个数字，为什么？
5. 哪条反馈帮助你改正了判断，哪条仍不清楚？
6. 请不用诊断提示，写出一个异常的两个可能原因。
7. 你希望复盘记录保留什么，下一次学习从哪里继续？
8. 如果用于实际客户任务，还缺哪些资料、权限或负责人确认？

保留角色、日期、任务、原话或观察、完成情况与待验证解释。访谈事实和产品假设分开，不以“你是不是需要 AI 助手”诱导答案。

## 推广与求职展示练习

可准备一页使用说明、三分钟演示与反馈表。演示顺序为六课入口、默认模拟、一次变更、复盘导出，再展示独立案例诊断与 SQL。评价首次正确完成和能否解释取舍；实际客户启用、复用及支持成本需要真实试点数据。

作品集展示已经实现的学习路径、参数模型、数据隔离、口径和边界；个人求职陈述补上本人真实完成的操作、改动和复核，见 [复盘与面试](interview.md)。
